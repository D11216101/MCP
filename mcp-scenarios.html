維運 Operations

1
部署後例行健康檢查
觸發：CI/CD pipeline 完成後自動呼叫 → 產出 Pass/Fail 報告，決定是否回滾
InstanaLibertyMQDb2GDP
1
GDP — 確認 S-TAP 在線、監控政策已安裝list_stapslist_installed_policies
2
Instana — 取得整體健康摘要與新增問題get_health_summarylist_open_issues
3
Liberty — 確認應用 STARTED、JVM / Thread Pool 正常get_application_detailsget_jvm_summaryget_threadpool_summary
4
IBM MQ — 確認 QM 運行，主要佇列無積壓dspmqrunmqsc: DISPLAY QSTATUS
5
Db2 — 確認連線正常、Tablespace 空間充足health_checkget_tablespace_usage
輸出：各項 Pass/Fail 清單 + 彙總結論，可直接回傳給 CI/CD webhook
2
服務效能劣化根因分析
觸發：Instana 告警 — P99 latency 或 errRate 超過閾值

1
Instana — 找錯誤 Span，取 trace_idsearch_spans(error_only=true)
2
Instana — 展開呼叫鏈，定位最先失敗的 span 與服務get_trace(trace_id)
3a
若失敗點在 Liberty → Liberty 確認 datasource / thread poolget_datasource_summaryget_threadpool_summary
3b
若失敗點在 Db2 → Db2 找慢 SQL 與鎖定get_active_sqlget_db2_runtime(locks)read_db2diag
輸出：根因層（Liberty/DB）+ 具體錯誤描述 + 建議修復動作
3
訊息積壓診斷
觸發：MQ 監控告警，或 Instana 偵測到 consumer service 有問題

▍建議程式架構

觸發方式

  • Webhook：CI/CD pipeline 呼叫（情境 1, 9）
  • 排程：cron job 每日/週觸發（情境 10, 14）
  • 告警回呼：Instana / QRadar Alert 觸發（情境 2~8, 15）
  • 自然語言：Bob 對話即時觸發（全部情境）

執行策略

  • 並行查詢：無依賴的 MCP 調用同時發出
  • 條件分支：Trace 結果決定下一步查哪個 MCP
  • 早期終止：Gate Check 第一個失敗即回傳 NO-GO
  • 逐層深入：從 APM 外層往 DB 內層鑽取

輸出格式

  • 結構化 JSON：供 CI/CD / webhook 消費
  • HTML 報告：管理層 / 審計用（Bob artifact）
  • 告警訊息：Slack / Teams / Email 通知
  • Offense Note：直接寫回 QRadar 留存

共用資料欄位

  • time_window：各情境統一時間範圍
  • service_name：跨 MCP 關聯服務
  • db_host / datasource：跨 Db2+GDP 關聯
  • source_ip：QRadar + GDP 威脅情報關聯
